# Обзор архитектуры JKNet

Этот документ описывает устройство лаунчера JKNet: из каких частей он состоит, как они связаны, что лежит на диске и какие команды доступны фронтенду. Читатель — разработчик или ИИ-агент, который продолжает работу над лаунчером. Документ относится к ветке `slice/servers`: каркас репозитория и браузер серверов поверх него.

## Компоненты

| Компонент | Технология | Ответственность |
| --- | --- | --- |
| Ядро | Rust, Tauri 2 | Файлы на диске, реестр Windows, настройки, будущие сеть и запуск игры |
| Фронтенд | React 19, TypeScript, Vite 8 | Экраны, состояние интерфейса, вызовы команд |
| Оформление | Tailwind CSS v4 | Токены из Figma, утилиты, типографика |
| Окно | WebView2 | Одно окно `main` без системного заголовка |

Фронтенд не имеет прямого доступа к файловой системе. Всё, что требует диска или реестра, проходит через команду ядра.

## Как компоненты взаимодействуют

1. `src-tauri/src/lib.rs` собирает приложение: подключает плагины, кладёт `AppState` в состояние Tauri, регистрирует команды.
2. `AppState::bootstrap` находит `%LOCALAPPDATA%\JKNet`, читает `settings.json` и создаёт папки данных. Функция не падает: лаунчер обязан открыть окно даже с нечитаемыми настройками.
3. React монтирует `App`, который поднимает `QueryClientProvider` и `HashRouter`.
4. Компонент вызывает хук из `src/lib/queries.ts`, хук вызывает обёртку из `src/lib/ipc.ts`, обёртка вызывает `invoke`.
5. Команда возвращает значение или `AppError`. Ошибка приходит на фронтенд строкой, её печатает `errorMessage`.

## Раскладка на диске

Папка конфигурации всегда `%LOCALAPPDATA%\JKNet`. В ней лежит `settings.json`. Папки данных лежат там же. Настройка `dataDirOverride` переносит их по другому абсолютному пути.

```text
%LOCALAPPDATA%\JKNet\
  settings.json
  clients\
    everyday\
      client.json        id, name, engineId, engineVersion, createdAt
      engine\            файлы движка
      home\base\         fs_homepath клиента: конфиги, скриншоты, моды
  library\               скачанные pk3
  cache\
    servers.json         последний удачный список серверов
  logs\                  журналы tauri-plugin-log
```

Идентификатор клиента — slug имени: строчные ASCII-буквы, цифры и дефисы. Slug задаётся при создании и не меняется при переименовании: путь, который сохранила другая часть лаунчера, должен оставаться рабочим.

Папка игры остаётся только для чтения. Лаунчер проверяет наличие `base\assets0.pk3`–`assets3.pk3` и больше ничего в ней не трогает.

## Поиск папки игры

Команда `detect_game_files` собирает кандидатов из трёх источников и снимает дубликаты по пути.

| Источник | Как ищет |
| --- | --- |
| `configured` | путь из `settings.json` |
| `steam` | `HKCU\Software\Valve\Steam\SteamPath`, затем `steamapps\libraryfolders.vdf`, затем папки `steamapps\common\*` с «jedi academy» в имени |
| `gog` | `HKLM\SOFTWARE\WOW6432Node\GOG.com\Games\*` с подходящим `gameName`, а также папки `C:\GOG Games\*` |

Кандидат отдаёт путь, источник, состояние четырёх архивов и флаг `valid`. Кандидат из сканирования попадает в список, только если все четыре архива на месте. Сохранённый путь показывается всегда, даже сломанный: иначе пользователь не поймёт, почему лаунчер не работает.

Команда `inspect_game_files` проверяет одну папку, выбранную в диалоге. Если пользователь указал корень установки, команда сама спускается в `GameData`.

## Браузер серверов

Модуль `servers/` спрашивает у мастер-серверов Quake 3 список адресов, опрашивает каждый адрес и отдаёт экрану **Servers** готовые строки. Форматы пакетов прочитаны в исходниках OpenJK, ветка `master`, коммит `1a6a6434`.

| Факт | Файл OpenJK |
| --- | --- |
| Заголовок `\xff\xff\xff\xff` без завершающего нуля | `codemp/qcommon/net_chan.cpp`, `NET_OutOfBandPrint` |
| Мастер-серверы `masterjk3.ravensoft.com` и `master.jkhub.org`, порт 29060 | `codemp/qcommon/qcommon.h:217` |
| Протокол 26 для версии 1.01 | `codemp/qcommon/qcommon.h:214` |
| Запрос `getservers 26` | `codemp/client/cl_main.cpp:3446` |
| Ответ `getserversResponse`: `\`, 4 байта адреса, 2 байта порта в сетевом порядке | `codemp/client/cl_main.cpp:1723` |
| Ответ `infoResponse\n<infostring>` и его ключи | `codemp/server/sv_main.cpp:553` |
| Ответ `statusResponse\n<infostring>\n<игроки>` | `codemp/server/sv_main.cpp:465` |
| Порядок `gametype_t`: FFA, Holocron, Jedi Master, Duel, Power Duel, Single Player, Team FFA, Siege, CTF, CTY | `codemp/game/bg_public.h:234` |
| Цветовые коды `^0`–`^9` | `shared/qcommon/q_color.h:15` |

### Как проходит обновление

Команда `refresh_servers` работает в два этапа.

1. Оба мастер-сервера опрашиваются одновременно, бюджет каждого — 1,5 с. Адреса сливаются в множество и теряют дубли. Мастер, который не прислал ни одной датаграммы, считается недоступным: `masterjk3.ravensoft.com` отвечает на DNS, но молчит, и пустой список от него нельзя путать с ответом «никто не играет».
2. Каждому адресу уходит `getinfo` со случайным `challenge`. Одновременно открыто не больше 64 сокетов, на попытку отводится 1 с, попыток две. Пинг строки — время обхода того запроса, на который пришёл ответ.

Команда возвращает полный список и параллельно шлёт события. Аргумент `masters` заменяет пару стандартных мастер-серверов; пустой список означает «взять стандартные».

| Событие | Полезная нагрузка | Когда |
| --- | --- | --- |
| `servers:batch` | `{ servers: ServerInfo[] }` | раз в 100 мс, пока идёт опрос |
| `servers:done` | `{ total, responded, elapsedMs }` | один раз в конце |

Ошибку команда возвращает только тогда, когда не ответил ни один мастер-сервер. Экран показывает плашку «Could not reach the master servers» с кнопкой **Retry** и продолжает показывать список из кеша.

### Кеш, доверие, избранное

Удачное обновление пишет `cache\servers.json`. Команда `get_cached_servers` читает этот файл и заново проставляет два флага, поэтому звезда, поставленная после последнего опроса, видна сразу. Нечитаемый кеш равносилен отсутствующему: следующее обновление перезапишет файл.

Доверенные серверы лежат в ресурсе `src-tauri/resources/trusted_servers.json` и попадают в установщик через поле `bundle.resources`. Файл поставляется пустым массивом: комментарии в JSON невозможны, поэтому форма записи описана здесь.

```json
[
  {
    "address": "203.0.113.10:29070",
    "name": "EU FFA",
    "community": "JKHub",
    "url": "https://jkhub.org"
  }
]
```

Ключ `address` сравнивается с полем `address` строки точно, вместе с портом. Список читается один раз за запуск. Если ресурс отсутствует или сломан, ядро пишет предупреждение в журнал и работает с пустым списком.

Избранное и история живут в `settings.json`. Поле `favoriteServers` — массив адресов, поле `serverHistory` — массив записей `{ address, lastConnected }`, новые впереди, не длиннее 50 записей. Команда `set_server_favorite` переключает звезду, `add_server_history` записывает подключение. Обе возвращают целый документ настроек, чтобы фронтенд обновил свой кеш без второго вызова.

### Что проверено на живой сети

Проверку выполняет тест `talks_to_the_real_masters` в `src-tauri/src/servers/mod.rs`. Он помечен `#[ignore]`, потому что ходит в интернет.

```
cargo test --lib -- --ignored --nocapture talks_to_the_real_masters
```

Результат от 10 сентября 2026 г.: 232 адреса от мастер-серверов, 194 сервера ответили за 4,1 с. Второй тест `each_master_answers_on_its_own` показал, где взялись эти адреса: `master.jkhub.org` отдаёт 232 записи за 153 мс, `masterjk3.ravensoft.com` не отвечает вовсе и съедает весь свой бюджет в 1,5 с.

## Работа без Tauri

Тот же фронтенд открывается двумя способами. Команда `npm run tauri dev` кладёт его в окно WebView2, где работают все API Tauri. Команда `npm run dev` отдаёт его обычному браузеру: этот режим показывает вёрстку и токены без сборки ядра.

В браузере объекта `window.__TAURI_INTERNALS__` нет, и вызов Tauri бросает `TypeError` до того, как успеет отклонить промис. Проверку берёт на себя функция `isTauri` из `src/lib/runtime.ts`. Она закрывает четыре места:

- Обёртки в `src/lib/ipc.ts` отклоняют промис с сообщением `Tauri runtime is not available`. Экраны печатают его в своей плашке ошибки и показывают пустые состояния.
- Кнопки окна в `TitleBar` и подписка на `onResized` ничего не делают.
- Кнопка **Open JKNet folder** остаётся выключенной.
- Перенаправление консоли в журнал не подключается.

## Окно и разрешения

Окно `main` создаётся без системного заголовка: `decorations: false`, размер 1280×800, минимум 1100×700, фон `#0B0E14`. Заголовок рисует компонент `TitleBar`. Атрибут `data-tauri-drag-region` стоит на самой полосе и не наследуется потомками, поэтому кнопки окна остаются нажимаемыми.

Файл `src-tauri/capabilities/default.json` выдаёт окну `main`:

| Разрешение | Зачем |
| --- | --- |
| `core:default` | базовый набор: события, путь, ресурсы, чтение состояния окна |
| `core:window:allow-start-dragging` | перетаскивание за свой заголовок |
| `core:window:allow-minimize` | кнопка свернуть |
| `core:window:allow-toggle-maximize` | кнопка развернуть |
| `core:window:allow-close` | кнопка закрыть |
| `core:window:allow-is-maximized` | иконка кнопки развернуть следует за состоянием окна |
| `dialog:allow-open` | выбор папки `GameData` |
| `log:default` | `src/main.tsx` шлёт `console.warn` и `console.error` в журнал |
| `opener:default` | ссылки на JKHub во внешнем браузере |
| `opener:allow-open-path` | кнопка **Open JKNet folder** на экране **Settings** |
| `window-state:default` | сохранение положения и размера окна |

Разрешение `core:window:allow-is-maximized` входит и в `core:default`: там собраны читающие вызовы окна, включая подписку `onResized`. Список держит его отдельной строкой ради читаемости: так видно, что `isMaximized` вызывает именно `TitleBar`.

Разрешение `opener:default` открывает только ссылки, поэтому у `opener:allow-open-path` своя область: `$LOCALDATA/JKNet`, то есть `%LOCALAPPDATA%\JKNet`. Область статична, а `dataDirOverride` задаёт произвольный путь. Если папка данных перенесена, кнопка возвращает ошибку `forbidden path` (не проверено: окно не запускали). Чтобы кнопка работала и там, добавьте новый путь в ту же область.

Плагины подключены в `lib.rs`: `tauri-plugin-log` пишет в `logs\`, `tauri-plugin-dialog` открывает диалог папки, `tauri-plugin-opener` открывает ссылки и папку данных, `tauri-plugin-window-state` восстанавливает геометрию окна.

Цель `TargetKind::Webview` у журнала не подключена намеренно. Фронтенд сам пересылает консоль в плагин. Такая цель вернула бы те же строки обратно в консоль и зациклила журнал.

## Границы и ограничения

- Лаунчер поддерживает только Windows. Код поиска игры собран под `cfg(windows)`, на других системах он возвращает пустой список.
- Ядро ходит в сеть только за списком серверов: UDP, IPv4, порты мастер-серверов и игровых серверов. Запросы к JKHub и загрузка движков появятся вместе с соответствующими модулями.
- Браузер серверов не ищет серверы в локальной сети. Вкладка **LAN** выключена: широковещательный запрос по портам 29070–29073 не реализован.
- Окно с браузером не запускали: события `servers:batch` и `servers:done` проверены только по коду, а разрешение `core:event:default` входит в `core:default` (не проверено запуском).
- Политика CSP не задана (`"csp": null`). Задайте `default-src 'self'` после первого запуска окна и проверьте на нём шрифты, стили и вызовы `ipc:`. Чем позже вы включите политику, тем больше мест ломается за один раз.
- Экран **Onboarding** — заготовка. Первый запуск проходит через экран **Clients**.
