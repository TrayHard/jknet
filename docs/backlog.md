Документ фиксирует задачи лаунчера, которые пользователь поставил 2026-09-11 после двух проверок в дев-окне. Партий две. Вторая партия — пункты `B1`–`B21` по замечаниям к сборке `main` `5db2a60`, разбитые по экранам. Порядок работы по каждому пункту: разведка сабагентами → задание → реализация в отдельной ветке → ревью → слияние. Состояния: `разведка`, `задание`, `в работе`, `ревью`, `готово`.

### B1. Одно поле поиска на весь экран

На вкладке **Browse JKHub** стоит второе поле поиска с подсказкой «Search the whole catalog». Уберите его. Поиск по экрану ведёт одно поле в шапке страницы, и оно обслуживает все три вкладки.

Приёмка:

- Вкладка **Browse JKHub** обходится без собственного поля поиска.
- Поле шапки фильтрует установленные файлы на вкладке **Installed**.
- Поле шапки ищет по каталогу jkhub.org на вкладке **Browse JKHub**.
- Поле шапки фильтрует список обновлений на вкладке **Updates**.
- Переключение вкладок не сбрасывает запрос.
- Задержка ввода остаётся 150 мс: константа `DEBOUNCE_MS` в `src/components/library/JkhubBrowser.tsx`.

Решение по умолчанию: строка запроса общая для трёх вкладок и переживает их переключение. Состояние: `готово` (слито в `main` коммитом `924f1eb`, ревью пройдено; в окне не проверено).

## Главная: экран Home

### B4. Кнопки и меню у строки сервера

Отдельных кнопок **Play** и с тремя точками в строках серверов нет. Кнопка с тремя точками появляется рядом с кнопкой подключения, когда сервер выделен:

- На экране **Servers** это панель сведений: кнопка с точками стоит рядом с кнопкой **Connect**.
- На экране **Home** клик по строке выделяет её, и в правой части строки появляются кнопка **Connect** и кнопка с точками.

Кнопка **Connect** подключает быстро: тем клиентом, с которого игрок последний раз заходил на этот сервер, а без такой записи — клиентом по умолчанию для игры. Идентификатор клиента берётся из записи истории, а не угадывается.

Меню кнопки с точками содержит три пункта:

- **Подключиться…** открывает модальное окно с деталями подключения, см. пункт B8.
- **Добавить в избранное** или **Убрать из избранного** переключает избранное по состоянию строки.
- **Скрыть** убирает сервер из всех списков.

Приёмка:

- Кнопка **Connect** и кнопка с тремя точками появляются только у выделенного сервера: в панели сведений экрана **Servers** и в строке экрана **Home**.
- Кнопка **Connect** запускает клиента из записи истории этого сервера, а без записи — клиента по умолчанию для игры.
- История подключений хранит идентификатор клиента: структура `ServerHistoryEntry` (`src-tauri/src/settings.rs:200`) получает поле клиента, и оба писателя истории (`HomePage.tsx:172`, `ServersPage.tsx:305`) его передают.
- Меню открывает три пункта, их имена лежат в каталоге `src/locales/en/`: интерфейс лаунчера пишется по-английски.
- Скрытый сервер не показывается нигде, кроме вкладки **Hidden** на экране **Servers**, и не попадает в счётчики.
- Вкладка **Hidden** возвращает сервер в списки.
- Скрытые серверы хранятся в настройках по образцу `favorite_servers` (`src-tauri/src/settings.rs:130`): готового поля `hiddenServers` в репозитории нет.

Компонента меню в UI-ките тоже нет: портал, привязка к триггеру и закрытие по клику снаружи реализованы один раз внутри `src/components/ui/Select.tsx`. Срез либо выносит эту логику в общий компонент, либо повторяет её.

Ответ пользователя закрывает оба вопроса пункта: отдельной кнопки **Play** в строке нет, а меню работает у выделенного сервера на обоих экранах.

Состояние: `задание`.

### B21. Ошибка: картинка карты в герое не грузится

Блок героя показывает пустое место вместо картинки карты последнего сервера. Журнал пишет ошибку с первой секунды после старта:

```
[tauri::protocol::asset][ERROR] asset protocol not configured to allow the path: …\cache\levelshots\ja__mp__ffa3.jpg
```

Область протокола `asset` задана в двух местах: статически в `src-tauri/tauri.conf.json` (`$APPLOCALDATA/cache/levelshots/**`) и во время выполнения функцией `levelshots::allow_cache_folder` (`src-tauri/src/levelshots.rs:1029`), которую вызывает `src-tauri/src/lib.rs:185`. Ни одна из двух не покрыла файл, который лаунчер сам положил в кеш.

Приёмка:

- Блок героя экрана **Home** показывает картинку карты последнего сервера.
- Область протокола `asset` покрывает папку кеша картинок карт при любом значении `dataDirOverride`: статическая запись и запись, добавленная во время выполнения, дают один и тот же путь.
- После старта в журнале нет строк `asset protocol not configured to allow the path`.
- Причина расхождения двух областей записана в [документе об архитектуре](architecture.md), раздел «Как картинка попадает в окно».

Состояние: `готово` (слито в `main` коммитом `8bef05b`, ревью пройдено; в окне не проверено).

### B12. Ошибка: окно настроек клиента открывается пустым

Кнопка настроек клиента открывает окно `client-<slug>` пустым, и окно не закрывается. Ошибка блокирует пункты B11 и B15, поэтому идёт первым срезом партии.

Причину чтением кода разведка не нашла. Отброшены разрешения окна, склейка URL с хешем `#/client/<slug>`, создание окна вне главного потока и падение дерева React из-за отсутствующего провайдера. Журнал `JKNet.log` показывает, что какая-то страница сессии восемнадцать раз выполнила код главного дерева — `FriendsProvider` и экран **Home**, — но какое это окно и когда оно потеряло маршрут, по журналу не видно. Поэтому первый срез даёт диагностику, а не исправление.

Первый срез, диагностика:

- Окно пишет в журнал свой фактический маршрут при загрузке: значение `window.location.href` до проверки `isClientWindowHash` (`src/App.tsx:56`). Плагин `log` уже подключён, нужен явный вызов уровня `info`: `forwardConsole` (`src/main.tsx:80`) пробрасывает только `console.warn` и `console.error`.
- Команда открытия окна и события окна пишут в журнал каждый свой исход, включая строки `client_window.rs:101,109`.
- Ошибки закрытия окна из `TitleBar` уходят в журнал: сегодня «команда не дошла» и «команда выполнилась и не сработала» по журналу неотличимы.

Что просить у пользователя после первого среза:

1. Воспроизведите ошибку в дев-окне и откройте инструменты разработчика пустого окна клиента: кнопка с шестерёнкой под дев-окном или сочетание **Ctrl+Shift+I**.
2. Пришлите текст консоли этого окна целиком, вместе с необработанными исключениями.
3. Пришлите строки `JKNet.log` за время воспроизведения и вывод терминала, где запущен `npm run tauri dev`: паника печатается в stderr процесса, а не через плагин `log`.

Приёмка:

- Журнал называет маршрут, который получило окно клиента, и исход команды открытия.
- Окно открывается заполненным: имя клиента, движок, папка мода, разделы параметров и предпросмотр командной строки.
- Окно закрывается своими элементами управления и не держит главное окно.
- Причина и исправление записаны в [документе об архитектуре](architecture.md).

### B16. Полный опрос показывает не все серверы

Кнопка **Get new list** приносит неполный список серверов.

Ответ пользователя: он видит и то, и другое — разное число серверов от нажатия к нажатию и пропажу конкретных известных серверов.

Факты разведки:

- Чтение ответа мастер-сервера корректно. Функция `query_master` (`src-tauri/src/servers/net.rs:98`) читает до маркера `\EOT` или до конца бюджета `MASTER_TIMEOUT`, как это делает сам движок. Датаграммы не теряются.
- Причина в том, что происходит после чтения. Команда `refresh_servers` спрашивает мастер-сервер один раз, а результат опроса целиком заменяет кеш (`write_cache_locked`, `src-tauri/src/servers/mod.rs:856`). Адрес, которого нет в новом ответе, исчезает из списка сразу, даже если секунду назад отвечал.
- Список самого мастер-сервера меняется без вмешательства сети: за окно в 45 с из примерно 238 адресов 13 присутствовали не во всех десяти запросах. Двадцать измерений пришли за 150–190 мс, все с маркером `\EOT`.
- Второй источник пропажи с мастер-сервером не связан: фильтр **Hide bot-only** включён по умолчанию и прячет около 17 % серверов, а правило `is_hidden_mod("mbii")` скрывает серверы MBII.
- Резервного мастер-сервера у Jedi Academy нет: из двух записей `src-tauri/src/game.rs:351` первая молчит годами.

Приёмка:

- Полный опрос сливает список мастер-сервера с адресами кеша, а не заменяет кеш целиком.
- Сервер уходит из списка после двух пропусков подряд: он не ответил ни на один из двух полных опросов. До этого он показан со статусом **Offline**.
- Журнал называет причину, по которой адреса нет в списке: нет у мастер-сервера, не ответил или скрыт фильтром.
- Запрос к мастер-серверу повторяется, если первый ответ пришёл без конца списка, маркера `\EOT`.
- Пустой список объясняет, какой фильтр скрыл серверы: такую строку уже даёт ключ `servers.empty.filteredBots`.

Состояние: `готово` (слито в `main` коммитом `8bef05b`, ревью пройдено; в окне не проверено).

Состояние: `готово` (слито в `main` коммитом `f752851`, ревью пройдено; команда `refresh_lan`, широковещательный `getinfo` на четыре порта дважды, константа `LAN_PORT_COUNT`; проверено тестом на `127.0.0.1`, в живой сети не проверено).

## 6. Полностью убрать статус Trusted

Механизм добавления доверенных серверов не придуман. Статус вырезается целиком: вкладка **Trusted**, бейджи и щит в таблице, файл `resources/trusted_servers.json`, поля в кеше и типах, упоминания в документации, глоссарии и дизайн-документе рабочей папки.

Приёмка: поиск по репозиторию по словам `trusted`, `Trusted`, `доверенн` не находит ничего, кроме записи в журнале изменений о том, что статус убран. Состояние: `готово` (слито в `main` коммитом `c94432d`, ревью пройдено; коммит `c663dfe`; в репозитории остаются слово `untrusted` в `Cargo.lock` как имя стороннего крейта и ключ `"trusted"` в фикстуре теста, который проверяет чтение старого кеша).

## 7. Параметры запуска у каждого клиента и отдельное окно клиента

### 7.1. Параметры запуска на клиент

Приёмка:

- У клиента появляется своё поле параметров запуска. Итоговая команда: общие параметры из настроек, затем параметры клиента, затем служебные токены лаунчера (`+connect` и подобные).
- Проверено и задокументировано, как движок разрешает повторы: при двух `+set r_mode` последний выигрывает; команды вида `+map`, `+connect`, `+exec` накапливаются и выполняются по порядку. Источник: обработка командной строки в OpenJK (`Com_ParseCommandLine`, `Com_StartupVariable`, `Com_AddStartupCommands`) и в JK2MV.
- Предупреждение о `s_initsound 0` для EternalJK учитывает оба источника аргументов.

### 7.2. Отдельное окно клиента

Пользователь хочет вместо модального диалога редактирования отдельное окно с детальным просмотром и редактированием клиента, где самые частые параметры запуска регулируются удобными элементами (не только текстовым полем).

Приёмка:

- Кнопка редактирования клиента открывает отдельное окно Tauri с заголовком клиента; окно переживает закрытие главного? Нет: закрывается вместе с приложением, но не блокирует главное окно.
- В окне: имя клиента, движок и его версия с кнопкой обновления, папка мода `fs_game`, разрешение и режим окна (`r_mode`, `r_customwidth`/`r_customheight`, `r_fullscreen`), звук (`s_volume`, `s_musicvolume`), имя игрока (`name`), максимальный FPS (`com_maxfps`), сеть (`rate`, `snaps`), поле дополнительных параметров и предпросмотр итоговой командной строки.
- Каждый удобный элемент пишет ровно один токен в параметры клиента и читает его обратно; ручной ввод в текстовое поле не теряется.
- Макет описан в дизайн-документе рабочей папки; файл Figma в этой сессии недоступен, пометка «(не проверено)».

Открытые вопросы: список «самых частых» параметров согласовать с пользователем; поведение при двух окнах одного клиента. Состояние: 7.1 — `готово` (слито в `main` коммитом `ee18545`, ревью пройдено, правки по ревью `b35b27b` и `d749a1e`: лимиты движка считаются байтами, помещается 31 сегмент с `+`), 7.2 — `готово` (слито в `main` коммитом `8621b06`, ревью пройдено, правки `5ad3f8e` и `479f3c2`; окно `client-<slug>`, команды `open_client_window`, `read_launch_cvars`, `write_launch_cvar`, `preview_launch_args`; диалог **Client settings** удалён; окно никем не открывалось, первым его откроет пользователь в дев-окне).
