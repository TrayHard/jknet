# Бэклог JKNet от 2026-09-11

Документ фиксирует задачи лаунчера, которые пользователь поставил 2026-09-11 после двух проверок в дев-окне. Партий две. Вторая партия — пункты `B1`–`B20` по замечаниям к сборке `main` `5db2a60`, разбитые по экранам. Первая партия — пункты `1`–`11` по замечаниям к версии 0.3.0 (`main` `28a129f`), все её пункты закрыты. Буква `B` в номере отличает вторую партию от первой. Каждый пункт содержит формулировку задачи, критерии приёмки, открытые вопросы и состояние. Порядок работы по каждому пункту: разведка сабагентами → задание → реализация в отдельной ветке → ревью → слияние. Состояния: `разведка`, `задание`, `в работе`, `ревью`, `готово`.

Правило процесса: сабагенты никогда не запускаются на модели Fable. Fable только оркестрирует. Код, документы и дизайн пишут агенты на Opus, разведку, проверки и факт-чек делают агенты на Sonnet, Haiku допустим для механических задач.

## Библиотека: экран Library

### B1. Одно поле поиска на весь экран

На вкладке **Browse JKHub** стоит второе поле поиска с подсказкой «Search the whole catalog». Уберите его. Поиск по экрану ведёт одно поле в шапке страницы, и оно обслуживает все три вкладки.

Приёмка:

- Вкладка **Browse JKHub** обходится без собственного поля поиска.
- Поле шапки фильтрует установленные файлы на вкладке **Installed**.
- Поле шапки ищет по каталогу jkhub.org на вкладке **Browse JKHub**.
- Поле шапки фильтрует список обновлений на вкладке **Updates**.
- Переключение вкладок не сбрасывает запрос.
- Задержка ввода остаётся 150 мс: константа `DEBOUNCE_MS` в `src/components/library/JkhubBrowser.tsx`.

Решение по умолчанию: строка запроса общая для трёх вкладок и переживает их переключение. Состояние: `разведка`.

### B2. Убрать лишние тексты и элементы экрана

Экран перегружен пояснениями. Уберите с него шесть элементов:

- подзаголовок под заголовком страницы «клиент · движок · файлов: N · включено: N · размер», ключ `library.subtitleClient`
- пояснение рядом с селектором клиента «Files are installed into this client only…», ключ `library.clientBar.hint`
- кнопку **Update categories** и значок обновления рядом с заголовком **Categories**, ключи `jkhub.tree.update` и `jkhub.tree.updating`
- строку области над сеткой карточек «Audio · installs into КЛИЕНТ», ключи `jkhub.scope.*`
- строку состояния каталога «Catalog indexed N ago · N files» вместе с кнопкой **Rebuild**, ключи `jkhub.index.line*` и `jkhub.index.rebuild`
- бейдж **From cache**, ключ `jkhub.fromCache`

Бейдж **From cache** пользователь называет «блямба „ИЗ КЕША“». Точное место бейджа разведка находит по коду.

Приёмка:

- Перечисленные тексты и элементы не рисуются ни на одной вкладке экрана **Library**.
- На экране остаются селектор клиента, сортировка и кнопка **Refresh**.
- Ключи локализации удалены вместе с элементами, и `npm run i18n:check` проходит.
- Действия **Rebuild** и **Update categories** доступны с экрана **Settings**.

Решение по умолчанию: оба действия переезжают в карточку **Cache** на экране **Settings**, где уже лежит перестроение кеша картинок карт. Функция сохраняется, экран **Library** разгружается.

Открытый вопрос: подтвердить переезд обоих действий или удалить их совсем. Состояние: `разведка`.

### B3. Карточка файла в каталоге JKHub

Кнопка установки занимает всю ширину нижней части карточки.

## Главная: экран Home

### B4. Кнопки и меню у строки сервера

В блоках **Favorites**, **History** и **Busiest servers** перед названием сервера стоят кнопка **Play** и кнопка с тремя точками. Кнопка с тремя точками открывает меню из четырёх пунктов:

- **Быстрое подключение** подключает тем клиентом, с которого игрок последний раз заходил на этот сервер; без такой записи берёт клиент по умолчанию для игры.
- **Подключиться…** открывает модальное окно с деталями подключения, см. пункт B8.
- **Убрать из избранного** или **Добавить в избранное** переключает избранное по состоянию строки.
- **Скрыть** убирает сервер из всех списков.

Приёмка:

- Строка сервера в трёх блоках экрана **Home** несёт кнопку **Play** и кнопку с тремя точками.
- Меню открывает все четыре пункта.
- Имена пунктов лежат в каталоге `src/locales/en/`: интерфейс лаунчера пишется по-английски.
- История подключений хранит идентификатор клиента, поэтому последний клиент сервера берётся из записи, а не угадывается.
- Скрытый сервер пропадает из всех списков и из счётчиков.
- На экране **Servers** появляется вкладка **Hidden**, откуда скрытый сервер возвращают в списки.
- То же меню открывается у строк таблицы на экране **Servers**: по кнопке с тремя точками и по правому щелчку.

Решения по умолчанию: кнопка **Play** делает то же, что быстрое подключение; меню работает и на экране **Servers**; скрытые серверы не попадают ни в счётчики, ни на экран **Home**.

Открытые вопросы: нужно ли то же меню на экране **Servers**; равна ли кнопка **Play** быстрому подключению. Состояние: `разведка`.

### B8. Модальное окно подключения

Пункт **Подключиться…** открывает модальное окно с деталями подключения. Окно зависит от профилей игрока (пункт B15) и от исследования скинов, рукояток и никнеймов. Содержимое окна:

- выбор клиента
- переключатель между ручным заполнением и выбором профиля игрока
- выпадающий список профилей с поиском, когда выбран профиль
- никнейм, скин, рукоятка меча и параметры запуска, когда игрок заполняет поля вручную

Приёмка:

- Кнопка **Подключиться** запускает выбранный клиент с `+connect` и выбранными значениями.
- Параметры запуска из окна дописываются после общих параметров настроек и параметров клиента.
- Никнейм сохраняется и выбирается из сохранённых, а поле раскрашивает цветовые коды `^0`–`^9`.
- Скин и рукоятка выбираются картинками, если исследование подтвердит такую возможность; иначе поля принимают код скина и имя рукоятки.
- Окно открывается с экранов **Home** и **Servers** одним компонентом.

Решение по умолчанию: сохранённые никнеймы лежат одним списком в настройках лаунчера, а не у каждого клиента.

Открытый вопрос: список никнеймов общий или свой у каждого клиента. Состояние: `разведка`.

### B11. Карточка клиента

Образец раскладки — карточка клиента «Regular ETJK». Карточка несёт логотип движка, имя клиента с бейджем **Default**, кликабельное название движка, дату создания, кнопки **Check updates**, настроек и **Delete**, кнопку **Launch** и кнопку открытия папки клиента.

Приёмка:

- Вместо букв в карточке стоит логотип движка.
- Заголовок карточки содержит имя клиента и бейдж **Default** у клиента по умолчанию.

- Кнопка **Make default** убрана с карточки и доступна в окне настроек клиента.

Если открыть папку не выйдет, кнопка не добавляется, а причину разведка записывает в этот пункт.

Решение по умолчанию: логотипы движков берутся из репозиториев движков, если файлы есть и лицензия разрешает их использование; иначе рисуются монограммы в стиле лаунчера.

Открытый вопрос: подтвердить источник логотипов. Состояние: `разведка`.

### B15. Профили игрока у клиента

Профиль игрока хранит название, никнейм, скин и рукоятку меча. Профилями управляют в окне настроек клиента, а выбирают их в окне подключения из пункта B8.

Правило «профилей в JKNet нет» из `jknet/CLAUDE.md` и глоссария рабочей папки относится к профилям поверх клиента. Профиль игрока — четвёртая сущность модели по решению пользователя от 2026-09-11. Глоссарий, `CLAUDE.md` и документ о дизайне лаунчера обновляются тем же изменением, что и код.

Приёмка:

- У клиента заводится список профилей игрока; профиль создают, переименовывают и удаляют в окне настроек клиента.
- Профиль хранит название, никнейм, скин и рукоятку меча.
- Поле никнейма сохраняет введённые имена, даёт выбрать их из сохранённых и раскрашивает цветовые коды `^0`–`^9`.
- Скин и рукоятка выбираются картинками, если исследование подтвердит такую возможность; иначе поля принимают код скина и имя рукоятки.
- Выбранный профиль превращается в токены командной строки при запуске клиента.
- Глоссарий, `jknet/CLAUDE.md` и документ о дизайне лаунчера описывают четыре сущности и отличают профиль игрока от клиента.

Открытые вопросы: какие поля запуска несёт профиль, только `name`, `model`, `saber1` и `saber2` или ещё цвет меча и `char_color_*`; нужен ли клиенту профиль игрока по умолчанию. Состояние: `разведка`.

## Список серверов: экран Servers

### B16. Полный опрос показывает не все серверы

Кнопка **Get new list** приносит неполный список серверов. Разведка выясняет причину и предлагает исправление. Гипотезы для проверки:

- мастер-сервер отвечает несколькими датаграммами, и часть из них теряется
- мастер-сервер иногда отдаёт короткий список
- ответ читается не до конца бюджета опроса
- фильтры по умолчанию скрывают серверы из одних ботов и серверы MBII, и это выглядит как пропажа

Приёмка:

- Причина названа измерением на живом мастер-сервере, а не догадкой.
- Полный опрос объединяет адреса мастер-сервера с адресами из кеша, которые ещё отвечают.
- Запрос к мастер-серверу повторяется дважды, и адреса из ответов объединяются.
- Пустой список объясняет, какой фильтр скрыл серверы: такую строку уже даёт ключ `servers.empty.filteredBots`.

Решение по умолчанию: полный опрос объединяет адреса мастер-сервера с живыми адресами кеша, запрос к мастер-серверу повторяется дважды.

Открытый вопрос: что именно пользователь видит как пропажу, разное число серверов от раза к разу или отсутствие конкретных известных серверов. Состояние: `разведка`.

Состояние: `разведка`.

## Первый запуск: онбординг

### B19. Убрать левую панель онбординга

## 1. Убрать серверы MBII из общего списка

Movie Battles II — отдельный глобальный мод со своим лаунчером. Пока лаунчер его не поддерживает, серверы MBII не должны попадать в список, а сам мод исключается из перечня поддерживаемых.

Приёмка:

- Серверы с модом `MBII` (значение `fs_game`/`game` в ответе `getinfo`, регистр не важен) не показываются ни на одной вкладке браузера серверов и не считаются в заголовке «N servers · M players».
- Упоминания MBII как поддерживаемого мода убраны из документации и интерфейса; в документе архитектуры записано, почему серверы отфильтрованы и как это отменить.
- Фильтр реализован одним правилом в ядре, чтобы будущая поддержка MBII включалась в одном месте.

Открытые вопросы: точное имя мода в `getinfo` у актуальных серверов MBII (по снимку списка: `MBII`); нужно ли показывать счётчик скрытых серверов MBII. Состояние: `готово` (слито в `main` коммитом `c94432d`, ревью пройдено; живая проверка 2026-09-11: у 9 из 29 ответивших серверов ключ `game` равен `MBII`, других написаний нет; коммит `7644ec4`, правило `is_hidden_mod` в `src-tauri/src/servers/mod.rs`; упоминаний MBII как поддерживаемого мода в репозитории не было).

## 4. Свой лоадер у каждой вкладки; избранное опрашивается напрямую

Решение пользователя от 2026-09-11: опрос серверов остаётся в Rust-ядре лаунчера (`src-tauri/src/servers/`), библиотека `jka-core` не подключается. Разведка `jka-core` записана в `notes/recon-jka-core.md` рабочей папки: библиотека на TypeScript для Node.js, из протокола в ней есть только `getstatus` на один адрес и `rcon status`.

Требования пользователя:

- Индикатор загрузки должен быть свой у каждой вкладки списка серверов (**All**, **Favorites**, **History**, **LAN**), а не общий.
- Избранные серверы опрашиваются отдельным механизмом: прямым запросом к сохранённым адресам, без мастер-сервера.

Приёмка:

- В ядре появляется команда опроса заданного списка адресов без мастер-сервера: `getinfo`, при необходимости `getstatus`, с тем же разбором ответов, что и у общего обновления.
- Вкладка **Favorites** опрашивает только сохранённые адреса и показывает свой индикатор; **All**, **History** и **LAN** имеют свои. Опрос одной вкладки не сбрасывает списки других.
- Вкладка **History** опрашивает адреса истории тем же механизмом, что и избранное (решение по умолчанию).

Состояние: `готово` (слито в `main` коммитом `f752851`, ревью пройдено; команда `refresh_addresses`, область `scope` в событиях, индикатор на каждую вкладку, строки без ответа помечены **Offline**, замок на запись кеша по игре; в окне не проверено).

## 7. Параметры запуска у каждого клиента и отдельное окно клиента

### 7.1. Параметры запуска на клиент

Приёмка:

- Проверено и задокументировано, как движок разрешает повторы: при двух `+set r_mode` последний выигрывает; команды вида `+map`, `+connect`, `+exec` накапливаются и выполняются по порядку.
