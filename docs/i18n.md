# Локализация лаунчера

Этот документ описывает, как JKNet говорит на восьми языках: где лежат каталоги строк, как экран получает текст, как добавить строку и как добавить язык. Читатель — разработчик лаунчера или переводчик, который заполняет одну папку. Документ относится к ветке `slice/i18n` репозитория `jknet`.

Восемь языков: английский, русский, украинский, немецкий, французский, испанский, польский и венгерский. Английский — исходный язык: с него переводят, и на него откатывается любой пропуск.

## Что уже сделано

| Язык | Состояние | Файл-маркер |
| --- | --- | --- |
| `en` | исходный язык | `src/locales/en/_status.json`, `state` равен `source` |
| `ru` | переведён полностью | `state` равен `translated` |
| `uk`, `de`, `fr`, `es`, `pl`, `hu` | папки заведены, во всех ключах английский текст | `state` равен `needs-translation` |

Шесть непереведённых языков уже доступны в списке настроек. Пока их не заполнили, интерфейс на них показывает английский текст, а карточка **Language** говорит об этом строкой «This language is not translated yet and shows English».

## Устройство

### Библиотека и загрузка каталогов

Перевод выполняют `i18next` и `react-i18next`. HTTP-бэкенда нет: каталоги — это статические файлы JSON, которые собирает Vite.

- Английский вшит в основной пакет. Он служит запасным ответом для любого языка, поэтому обязан быть в памяти всегда.
- Остальные семь языков лежат в отдельных чанках. Функция `loadLanguage` в `src/i18n/index.ts` подтягивает их динамическим `import()`, поэтому лаунчер на английском не скачивает и не разбирает ничего лишнего.
- Запасной язык один для всех: `fallbackLng` равен `en`. Цепочек между языками нет. Украинский с пропущенным ключом покажет английский текст, а не русский.

Каталог загружается до монтирования React: функция `start` в `src/main.tsx` ждёт `bootstrapI18n`. Первый кадр сразу выходит на нужном языке. Без этого окно моргало бы английским и переверстывалось: «Настройки» шире, чем «Settings».

### Раскладка файлов

```text
src/i18n/

  languages.ts        список языков и чистое правило выбора
  resources.d.ts      типы ключей из английских каталогов
  errors.ts           перевод отказа команды по коду ошибки
  useFormat.ts        числа, размеры, даты и длительности через Intl
  useGameLabels.ts    названия режимов игры по номеру
  useSystemLocale.ts  локаль операционной системы
  LanguageSync.tsx    следит за настройкой и переключает язык
src/locales/
  en/                 исходный язык: 14 файлов пространств имён
```

### Пространства имён

Четырнадцать файлов, по одному на экран или на сквозную тему.

| Пространство | Что в нём |
| --- | --- |
| `common` | кнопки, состояния, единицы измерения, заголовок окна |
| `nav` | боковая панель и переключатель игры |
| `home` | экран **Home**, уведомление о папке игры, список серверов |
| `servers` | экран **Servers**: фильтры, вкладки, таблица, панель сведений |
| `clients` | экран **Clients** и оба диалога клиента |
| `library` | экран **Library**: категории, карточки, конфликты, удаление |
| `jkhub` | вкладка **Browse JKHub** |
| `friends` | экран **Friends**, присутствие, заявки, приглашения |
| `account` | учётная запись и вход в JKNet Online |
| `settings` | экран **Settings**, включая карточки языка, кеша и «О программе» |
| `onboarding` | три шага первого запуска и панель бренда |
| `errors` | сообщения об отказах команд ядра, по коду ошибки |
| `games` | режимы игры, источники папки игры, стандартная подпись карты |
| `update` | обновление самого лаунчера |

Пространство — это экран, а не компонент. Строка переезжает между компонентами гораздо чаще, чем между экранами, а ключ, который приходится переименовывать при каждом рефакторинге, никто не удержит стабильным.

### Ключи

Ключи семантические и стабильные: `filters.mode`, `install.conflicts.title`. Английское предложение ключом не бывает.

- Подстановка: `{{name}}`. Экранирование выключено (`interpolation.escapeValue` равно `false`), потому что React экранирует всё сам, а второй проход превратил бы апостроф в имени сервера в `&#39;`.
- Разметку внутри сообщения задают номерные теги `<0>`, `<1>`. Компонент рисует такое сообщение через `<Trans>` и передаёт список элементов в `components`.
- Предложения из кусков не склеивают. Подзаголовок экрана **Servers** — исключение только на вид: его части — это законченные сообщения со своими подстановками, а точка-разделитель ` · ` остаётся пунктуацией в коде.

### Типы

Файл `src/i18n/resources.d.ts` объявляет `CustomTypeOptions` с ресурсами, выведенными из английских каталогов. Поэтому `t("servers.filters.mode")` дополняется редактором, а опечатка в ключе валит `npm run typecheck`. Ключ, вычисленный во время работы, типы проверить не могут: такие места собраны в трёх местах (`errors.ts`, `useGameLabels.ts`, `useStatusLine.ts`) и каждое сначала спрашивает `i18n.exists`.

### Множественное число

Формат JSON v4. Суффиксы ключа — категории CLDR того языка, которые выдаёт `Intl.PluralRules`.

| Язык | Формы |
| --- | --- |
| `en`, `de`, `hu` | `_one`, `_other` |
| `fr`, `es` | `_one`, `_many`, `_other` |
| `ru`, `uk`, `pl` | `_one`, `_few`, `_many`, `_other` |

Проверено запуском `Intl.PluralRules` в Node 24: для русского `1` даёт `one`, `2` — `few`, `5` и `0` — `many`. Форму `_other` русская папка тоже содержит: её выбирают дробные числа.

Скрипт `i18n-seed.mjs` разворачивает английскую пару в нужный набор сам, а `i18n-check.mjs` сверяет набор с `Intl.PluralRules` и падает на лишней или пропущенной форме.

### Выбор языка

Настройка `language` в `settings.json` принимает `system` или один из восьми идентификаторов. Значение по умолчанию — `system`.

Правило выбора — чистая функция `resolveLanguage` в `src/i18n/languages.ts`:

1. Настройка называет язык — берётся он.
2. Иначе берётся локаль операционной системы: `locale()` из `@tauri-apps/plugin-os`, а вне Tauri `navigator.language`.
3. Локаль сопоставляется по первой части тега: `de-AT` даёт `de`, `pt-BR` каталога не имеет и даёт `en`.

Ядро проверяет значение при записи. Функция `SettingsPatch::validate` в `src-tauri/src/settings.rs` отклоняет всё, кроме `system` и восьми идентификаторов, поэтому `settings.json` не может хранить язык, который лаунчер не умеет загрузить.

Строка **Language** стоит первой карточкой экрана **Settings**: игрок, который не читает остальной экран, обязан найти её. Варианты списка написаны на своих языках — «Русский», «Deutsch», «Magyar» — и никогда не переводятся. Пункт «Язык системы» называет язык, который он выберет.

Переключение применяется сразу. Патч возвращает документ настроек, компонент `LanguageSync` видит новое значение, загружает каталог и вызывает `changeLanguage`. Тот же вызов пишет `document.documentElement.lang`.

### Форматирование чисел, дат и размеров

Всё, что игрок читает как число, проходит через `Intl` с активной локалью. Разделитель разрядов, десятичная запятая, порядок дня и месяца, название единицы — всё это в восьми языках разное.

Связывает `Intl` и каталог хук `useFormat` в `src/i18n/useFormat.ts`:

| Вызов | Что даёт |
| --- | --- |
| `format.bytes(n)` | `12,4 МБ` — число через `Intl`, шаблон единицы из `common.units.bytes` |
| `format.number(n)` | `12 345` |
| `format.percent(r)` | `42 %` |
| `format.date(iso)` | `2 сент. 2026 г.` |
| `format.age(seconds)` | `12 с`, `3 мин`, `2 ч` — один разряд |
| `format.elapsed(seconds)` | `2 ч 14 мин` |
| `format.milliseconds(n)` | `45 мс` |

Название единицы взято из каталога, а не из `Intl`: `Intl.NumberFormat` со `style: "unit"` печатает 512 байт как «512 byte», и в узкой колонке таблицы это выглядит поломкой. Числовую часть по-прежнему форматирует `Intl`.

Чистые функции без React лежат в `src/lib/format.ts`: `splitBytes`, `splitAge`, `splitElapsed`, `formatNumber`, `formatDate`. Хук — это тонкая обёртка над ними.

### Ошибки ядра

Каждая команда возвращает отказ в виде `{ code, message, details }`. Файл `src-tauri/src/error.rs` даёт варианту `AppError` стабильное имя `code` в стиле camelCase и объект `details` со всеми значениями, которые подставляются в сообщение.

Фронтенд переводит отказ хуком `useErrorText` из `src/i18n/errors.ts`:

1. Читает конверт функцией `errorEnvelope` из `src/lib/ipc.ts`.
2. Ищет ключ `errors:<code>`; для варианта `online` берёт код контракта из `details` и ищет `errors:online.<код>`.
3. Ключа нет — печатает английское `message`, как его собрало ядро.

Запасной ответ всегда предложение, никогда пустая строка и никогда голый код. Тест `every_code_is_a_key_of_the_english_error_catalog` в `error.rs` читает английский каталог и падает, если у варианта нет ключа.

Журналы ядра не переводятся: они английские, и это делает строку журнала пригодной для поиска.

### Что переводу не подлежит

| Что | Почему |
| --- | --- |
| Имена серверов, названия карт, папки модов | это данные, их написал оператор сервера |
| Названия категорий и заголовки файлов JKHub | это данные сайта |
| Имена движков и их описания | это названия проектов из реестра в `engines.rs` |
| Jedi Academy, Jedi Outcast, `JA`, `JO` | имена собственные, приходят из таблицы `GameSpec` |
| JKNet, JKNet Online, JKHub, Discord, Steam, GOG | имена собственные |
| `pk3`, `fs_game`, `GameData`, имена cvar | идентификаторы |

Названия режимов игры — исключение. Номер приходит от сервера, а подпись к номеру лежит в `games.gametypes.<игра>.<номер>`: номер 7 — это Siege в Jedi Academy и CTF в Jedi Outcast, поэтому в ключе есть игра. Английская подпись из `GameSpec` остаётся запасным ответом.

### Шрифты

Chakra Petch, дисплейный шрифт макета, кириллицы не содержит: пакет `@fontsource/chakra-petch` даёт наборы `latin`, `latin-ext`, `thai` и `vietnamese`. Поэтому для двух кириллических языков дисплейный шрифт подменяется на Exo 2, у которого есть и латиница, и кириллица, и та же техничная, слегка узкая манера.

Правило лежит в `src/styles/fonts.css`:

```css
html[lang="ru"],
html[lang="uk"] {
  --font-display: "Exo 2", "Segoe UI", system-ui, sans-serif;
}
```

Селектор совпадает с атрибутом `lang`, который пишет `applyDocumentLanguage`. Правило стоит вне слоёв каскада и поэтому побеждает блок `@theme` из `src/index.css`. Объявлять токен второй раз внутри `@theme` нельзя: получилась бы циклическая ссылка, о которой предупреждает `CLAUDE.md`.

Тот же файл подключает шрифты по весам, а не по наборам символов. Файл `@fontsource/inter/latin-500.css` объявляет один `@font-face` без `unicode-range`, поэтому импорт `latin-500` и `latin-ext-500` рядом объявляет одно семейство дважды и второй выигрывает для всех символов. Файл по весу объявляет каждый набор со своим диапазоном, и браузер берёт только нужные. Это же исправление вернуло польские и венгерские буквы `ł ą ę ż ő ű`: прежние импорты `latin-*` их не несли.

## Как добавить строку

1. Добавьте ключ в английский файл нужного пространства имён: `src/locales/en/<пространство>.json`. Ключ семантический, значение — законченное предложение с подстановками.
2. Если у ключа есть число, заведите пару `_one` и `_other`.
3. Вызовите его в компоненте: `const { t } = useTranslation("servers")`, затем `t("filters.mode")`. Внутри строки с разметкой применяйте `<Trans>`.
4. Разложите ключ по остальным языкам: `npm run i18n:seed`. Скрипт допишет ключ в семь папок с английским текстом и развернёт множественное число под каждый язык. Уже переведённые значения он не трогает.
5. Переведите ключ в `src/locales/ru/`.
6. Прогоните `npm run i18n:check` и `npm run typecheck`.

Ключ, который приходится вычислять во время работы, сначала проверяйте вызовом `i18n.exists`, а `t` приводите к свободному типу в одном месте, как это сделано в `src/i18n/errors.ts`.

## Как добавить язык

1. Добавьте идентификатор в `LANGUAGES` в `src/i18n/languages.ts` вместе с родным названием языка.
2. Добавьте тот же идентификатор в константу `LANGUAGES` в `src-tauri/src/settings.rs`, иначе ядро отклонит настройку.
3. Выполните `npm run i18n:seed <язык>`. Скрипт создаст папку, разложит все 14 пространств имён с английским текстом и развернёт множественное число под правила этого языка.
4. Создайте `src/locales/<язык>/_status.json` со значением `state` равным `needs-translation`.
5. Добавьте язык NSIS в `bundle.windows.nsis.languages` файла `src-tauri/tauri.conf.json`. Имена берите из файлов языков NSIS: `English`, `Russian`, `Ukrainian`, `German`, `French`, `Spanish`, `Polish`, `Hungarian`.
6. Если у языка кириллическое или иное письмо, которого нет в Chakra Petch, добавьте его в селектор `html[lang=…]` в `src/styles/fonts.css`.
7. Прогоните `npm run i18n:check`.

## Как перевести язык

Переводчик работает в одной папке `src/locales/<язык>/` и больше нигде.

1. Прочитайте `src/locales/en/_notes.md`: там пояснения к ключам, у которых английский текст без контекста непонятен, и ограничения по длине.
2. Переведите значения в 14 файлах JSON. Ключи не трогайте.
3. Сохраните все подстановки `{{name}}` в том же написании. Порядок внутри предложения меняйте свободно.
4. Заполните все формы множественного числа своего языка.
5. Поставьте в `_status.json` значение `state` равным `translated`.
6. Прогоните `npm run i18n:check` из корня репозитория.

## Скрипт проверки

Файл `scripts/i18n-check.mjs`. Только Node, без зависимостей: он запускается из `prebuild`, и отсутствующий пакет ломал бы любую сборку.

Скрипт делает две проверки.

**Каталоги.** У каждой папки языка ровно те же пространства имён и ключи, что у английской. Значения не пустые, подстановки совпадают с английскими для того же ключа, набор форм множественного числа совпадает с ответом `Intl.PluralRules` для этого языка. Файл `_status.json` на месте и называет известное состояние.

**Экраны.** Ни один файл `.tsx` в `src/` не печатает собственное предложение. Скрипт ищет текстовые узлы JSX и атрибуты `placeholder`, `title`, `aria-label`, `alt`. Кандидат проходит, если состоит только из слов списка `scripts/i18n-allowlist.json`, цифр и пунктуации.

Запуск:

```
npm run i18n:check
```

Скрипт печатает каждую находку и возвращает `1`, если нашёл хоть одну. Он же выполняется перед `npm run build` через `prebuild` и отдельным шагом в `.github/workflows/ci.yml`.

Список разрешённых слов держите коротким. Слово попадает в него, только если интерфейс печатает его одинаково на всех языках: имя собственное, путь, идентификатор.
