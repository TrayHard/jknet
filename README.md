# JKNet

JKNet — лаунчер мультиплеера Star Wars Jedi Knight: Jedi Academy для Windows. Он ставит движки, запускает клиенты, хранит файлы pk3 каждого клиента и показывает список серверов. Steam не нужен: лаунчер только читает `base\assets0.pk3`–`assets3.pk3` из вашей копии игры и никогда не пишет в папку игры.

Работают все четыре основных экрана: **Home**, **Servers**, **Library** и **Clients**.

## Что работает

- **Поиск игры.** Лаунчер находит папку `GameData` в установках Steam и GOG, проверяет четыре архива ассетов и принимает папку, выбранную вручную.
- **Клиенты.** Клиент — именованный экземпляр движка со своими файлами и настройками. Лаунчер создаёт, переименовывает и удаляет клиенты, назначает клиент по умолчанию и задаёт папку мода `fs_game`.
- **Движки.** Реестр из четырёх сборок: OpenJK, EternalJK, TaystJK, jaMME. Лаунчер читает релизы с GitHub, скачивает архив для Windows x86, распаковывает его в папку клиента и проверяет обновление по тегу и времени публикации.
- **Запуск игры.** Лаунчер запускает исполняемый файл движка сам и раскладывает три корня файловой системы: `fs_cdpath` на папку игры, `fs_basepath` на распакованную сборку, `fs_homepath` на папку клиента. Одновременно живёт одна игра, лаунчер следит за процессом и умеет его остановить.
- **Браузер серверов.** Лаунчер спрашивает адреса у мастер-серверов `master.jkhub.org` и `masterjk3.ravensoft.com` по протоколу 26, опрашивает каждый сервер запросом `getinfo` и заполняет таблицу по мере ответов. Есть фильтры, вкладки **All**, **Trusted**, **Favorites**, **History**, список игроков и кнопка **Connect**.
- **Библиотека pk3.** Файлы принадлежат клиенту и лежат в его папке `home\`. Лаунчер устанавливает архивы перетаскиванием или через диалог, определяет категорию, включает и выключает файл переименованием, ищет конфликты внутренних путей и называет победителя по правилам движка.
- **Настройки.** Экран **Settings** показывает папку данных, открывает её в проводнике и задаёт поле **Extra launch arguments** — токены, которые дописываются в команду запуска любого клиента.
- **Обновление лаунчера.** Установленный лаунчер проверяет GitHub Releases, показывает уведомление о новой версии и ставит её по кнопке. Пакет проверяется по подписи minisign.

## Чего ещё нет

- Экран **Friends**, учётные записи и вход через JKHub или Discord — заготовки.
- Экран **Onboarding** — заготовка. Первый запуск проходит через экран **Clients**.
- Разделы настроек Downloads, Appearance и Account — заготовки. Работает только общий раздел.
- Вкладка **LAN** в браузере серверов выключена: широковещательный поиск не реализован.
- Вкладки **Browse JKHub** и **Updates** в библиотеке пусты: запросов к JKHub ядро не делает.

## Установка и обновление

Этот раздел для игрока. Разработчику нужен раздел [«Быстрый старт»](#быстрый-старт).

Установите лаунчер:

1. Скачайте файл `JKNet_0.1.0_x64-setup.exe` со [страницы релизов](https://github.com/TrayHard/jknet/releases/latest).
2. Запустите файл. Установщик не запрашивает права администратора: он пишет в папку текущего пользователя.
3. Необязательно: на последней странице установщика установите флажок **Create desktop shortcut**.
4. Откройте JKNet из меню **Пуск**, группа **JKNet**.

Установщик кладёт файлы так:

| Что | Куда |
| --- | --- |
| Программа | `%LOCALAPPDATA%\JKNet` |
| Ярлык | меню **Пуск**, группа **JKNet**; на рабочем столе — по флажку |
| Данные игрока | `%LOCALAPPDATA%\JKNet`: `settings.json`, `clients\`, `library\`, `cache\`, `logs\` |
| Путь установки | `HKCU\Software\JKNet\JKNet` |
| Запись в списке программ | `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\JKNet` |

> **Внимание.** Программа и данные игрока лежат в одной папке: установщик NSIS в режиме `currentUser` берёт путь `%LOCALAPPDATA%\ИМЯ_ПРОДУКТА`, а лаунчер держит там же свои файлы. Деинсталлятор удаляет по списку только то, что записал сам, поэтому папка с непустым `clients\` остаётся на месте (не проверено: деинсталлятор не запускали). Подробности — в разделе [«Что собирает установщик»](docs/architecture.md#что-собирает-установщик).

Обновление приходит само:

- Через 5 с после запуска лаунчер спрашивает у GitHub Releases файл `latest.json`.
- Если версия на сервере выше, лаунчер показывает уведомление `JKNet VERSION is available` с кнопкой **Install and restart**.
- Кнопка скачивает пакет, показывает ход загрузки и передаёт файл установщику. Установщик работает в режиме `passive`: он показывает полосу выполнения и ничего не спрашивает. После установки лаунчер запускается сам.

Чтобы проверить обновление вручную, откройте экран **Settings** и нажмите **Check for updates** на карточке **About**. Там же написана установленная версия.

Лаунчер проверяет подпись пакета алгоритмом minisign до того, как отдаст файл установщику. Пакет без подписи или с чужой подписью отклоняется. Ошибка проверки при запуске попадает только в журнал: игрок, который ни о чём не спрашивал, не должен видеть ответ. Ошибка проверки по кнопке видна на карточке **About**.

> **Примечание.** Сертификата Authenticode у сборки нет, поэтому при первом запуске установщика Microsoft SmartScreen показывает предупреждение. Подпись сертификатом — отдельное решение, см. [«Две подписи»](docs/architecture.md#две-подписи).

## Перед началом

Установите:

- Node.js 24 и npm 11;
- Rust stable с целью `x86_64-pc-windows-msvc` (`rustup default stable-msvc`);
- Visual Studio Build Tools 2022 с рабочей нагрузкой **Desktop development with C++**;
- WebView2 Runtime (Windows 11 содержит его по умолчанию).

## Быстрый старт

Если терминал открыт до установки Rust, команда `npm run tauri dev` падает с ошибкой `failed to run 'cargo metadata' ... program not found`: в унаследованном `PATH` нет папки `%USERPROFILE%\.cargo\bin`. Запустите вместо неё скрипт `..\scripts\run-jknet.ps1` из корня рабочей папки. Скрипт перечитывает `PATH` из реестра, добавляет папку cargo, ставит зависимости при первом запуске и выполняет ту же команду. Ключ `-Check` прогоняет проверки из раздела «Проверки», `-DryRun` печатает команды и ничего не запускает.

1. Установите зависимости фронтенда:
   ```bash
   npm install
   ```
2. Запустите приложение в режиме разработки:
   ```bash
   npm run tauri dev
   ```
   Команда поднимает Vite на порту 1420 и собирает Rust-ядро. Первая сборка занимает несколько минут.

   Чтобы посмотреть только вёрстку, выполните `npm run dev` и откройте `http://localhost:1420/` в браузере. Ядро в этом режиме не собирается: команды отвечают ошибкой `Tauri runtime is not available`, экраны показывают пустые состояния.
3. Соберите установщик:
   ```bash
   npm run tauri build
   ```
   Результат — `src-tauri/target/release/bundle/nsis/JKNet_0.1.0_x64-setup.exe`. На холодном кеше сборка занимает около десяти минут.

   Чтобы получить рядом файл подписи `.sig`, задайте ключ подписи обновлений перед сборкой:

   ```powershell
   $env:TAURI_SIGNING_PRIVATE_KEY = Get-Content "$env:USERPROFILE\.tauri\jknet.key" -Raw
   $env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = ""
   npm run tauri build
   ```

   Без этих переменных сборка создаёт установщик и падает следом, на шаге подписи: `A public key has been found, but no private key`. Так работает ключ `bundle.createUpdaterArtifacts` в `tauri.conf.json`. Файл `.sig` от прошлой сборки при этом остаётся на диске и уже не соответствует новому установщику, поэтому удалите его или пересоберите с ключом.

## Проверки

| Задача | Команда |
| --- | --- |
| Типы и сборка фронтенда | `npm run build` |
| Только типы | `npm run typecheck` |
| Компиляция ядра | `cargo check --all-targets` в `src-tauri` |
| Линтер Rust | `cargo clippy --all-targets -- -D warnings` в `src-tauri` |
| Модульные тесты Rust | `cargo test` в `src-tauri` |

Четыре теста помечены `#[ignore]`: они ходят в интернет или требуют установленную игру. Чтобы запустить их, добавьте `-- --ignored`.

Те же пять проверок выполняет процесс `.github/workflows/ci.yml` на бегунке `windows-latest` при каждом push и в каждом pull request.

## Выпуск версии

Релиз собирает процесс `.github/workflows/release.yml` по тегу `vX.Y.Z`. Он же публикует черновик релиза и файл обновлений `latest.json`.

### Перед началом

Заведите в репозитории два секрета GitHub Actions:

| Секрет | Значение |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | содержимое файла `%USERPROFILE%\.tauri\jknet.key` целиком |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | пустая строка: ключ выпущен без пароля |

Проверьте адрес обновлений: поле `plugins.updater.endpoints` файла `src-tauri/tauri.conf.json` указывает на `https://github.com/TrayHard/jknet/releases/latest/download/latest.json`. Смените его, если релизы уезжают в другой репозиторий. Пока опубликованных релизов нет, лаунчер проверяет обновления впустую: адрес отвечает ошибкой, лаунчер пишет её в журнал и работает дальше.

> **Предупреждение.** Приватный ключ существует в одном экземпляре и в репозиторий не попадает: `.gitignore` отклоняет `*.key`. Потеря ключа отрезает от обновлений все установленные лаунчеры: подпись новой сборки перестанет сходиться с полем `pubkey`, которое уже разошлось по машинам игроков. Сделайте резервную копию в менеджере паролей.

### Порядок выпуска

1. Поднимите версию в трёх файлах одним значением: `package.json`, `src-tauri/Cargo.toml` и `src-tauri/tauri.conf.json`. Версию берёт из `tauri.conf.json` и установщик, и обновление, а расхождение с `Cargo.toml` даёт разные номера в окне и в списке программ.
2. Обновите `Cargo.lock`: выполните `cargo check` в `src-tauri`.
3. Зафиксируйте изменения и поставьте тег:
   ```bash
   git commit -am "Версия 0.2.0"
   git tag v0.2.0
   git push origin main --tags
   ```
4. Дождитесь окончания процесса **Release** во вкладке **Actions**. Он собирает установщик, подписывает его и создаёт черновик релиза.
5. Проверьте вложения черновика: `JKNet_0.2.0_x64-setup.exe`, `JKNet_0.2.0_x64-setup.exe.sig` и `latest.json`.
6. Опубликуйте черновик кнопкой **Publish release**.

Установленные лаунчеры увидят версию после публикации: адрес `releases/latest/download/latest.json` черновики не отдаёт.

## Структура репозитория

| Папка | Содержимое |
| --- | --- |
| `src/` | фронтенд: React, TypeScript, Tailwind CSS |

## Где лежат данные

Лаунчер создаёт `%LOCALAPPDATA%\JKNet`:

| Путь | Содержимое |
| --- | --- |
| `settings.json` | настройки лаунчера |
| `clients\<slug>\` | клиент: `client.json`, `library.json`, папка `engine\`, папка `home\` |
| `library\` | скачанные pk3-файлы |
| `cache\` | список серверов `servers.json`, релизы движков, архивы сборок |
| `logs\` | журналы работы |

Настройка `dataDirOverride` переносит `clients`, `library`, `cache` и `logs` в другую папку. Файл `settings.json` остаётся в `%LOCALAPPDATA%\JKNet`.

Правьте `settings.json` вручную, когда лаунчер закрыт или когда поля не пересекаются: команда `update_settings` записывает только изменённые поля и перечитывает файл перед записью.
